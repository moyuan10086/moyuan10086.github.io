游戏结束

数组压缩 + 状态不可逆检测

用方向键或滑动移动方块，相同数字会合并。核心逻辑「压缩-合并-再压缩」三遍扫描，操作前后 JSON 快照比对决定是否生成新块。

数据结构4×4 二维数组，0 表示空格。每次操作沿方向逐行/列提取非零值→合并相邻等值→补零→写回。
不可逆判负棋盘填满且无相邻等值 → 游戏结束。用双重遍历检查水平/垂直邻居，O(16) 复杂度。
状态持久化最高分存 localStorage，页面刷新不丢失。

五子棋

黑方回合

Minimax + Alpha-Beta 剪枝

AI 搜索深度 4 层，候选节点由已落子邻域生成（空棋盘天元开局），Alpha-Beta 剪枝将复杂度从 O(bⁿ) 压缩到 O(√(bⁿ))。

棋型评分引擎四方向扫描线分析：五连(10⁷) > 活四(5×10⁵) > 冲四(8×10⁴) > 活三(5×10⁴) > 冲三(5×10³) > 活二(500)。防守权重 1.1x 偏保守。
候选节点生成仅搜索已有棋子 2 格邻域，每层取评分前 15 名，大幅缩减搜索树宽度。
悔棋实现历史栈记录每步坐标与颜色，人机模式一次撤销两步（人类+AI）。

飞行萝卜

Three.js 3D 动画场景

一个纯观赏性的 Three.js 3D 场景：胡萝卜载着兔子飞行员在云层中飞行。使用 TweenMax 驱动循环动画，OrbitControls 控制用户视角。

渲染管线WebGLRenderer → PerspectiveCamera → Scene + Fog 大气效果。DirectionalLight + AmbientLight 混合照明，PlaneBufferGeometry 做远景地面。
动画系统TweenMax 控制三个独立循环：胡萝卜上下浮动（yoyo）、左右摇摆（yoyo）、叶子持续旋转。兔子耳朵互逆摆动，眨眼用 scale.y→0.1 模拟。
网格建模所有角色均为程序化生成：CylinderGeometry 做身体、CubeGeometry 变形做翅膀/耳朵/座位。无外部模型文件，纯几何体组合。

一笔连珠

哈密顿路径 + 状态机碰撞

「不重复走完所有格子」在计算机科学中就是经典的哈密顿路径问题。关卡用 7×6 二维数组描述，事件链驱动精灵状态迁移。

关卡数据结构7×6 二维数组，0=空地 1=路径格 2=起点 3=终点。等价于 Tilemap 中的图节点，四邻接构成无向图。
图论建模每个路径格是一个节点，上下左右相邻格之间有一条边。问题等价于寻找恰好遍历每个节点一次的哈密顿路径，NP-完全问题。
精灵状态机tag 字段驱动三态：0=未访问 → 1=当前路径中 → 2=已完成。事件链：mousedown→mousemove→mouseup，每次移动检测坐标落入区域。
适配方案320×480 移动端原生尺寸，父页面用 transform:scale() 等比缩放。覆盖 parse() 防止二次调用导致 config.offset 类型错误。

俄罗斯方块

旋转矩阵 + 消行算法

七种标准方块（I/O/T/S/Z/J/L），每种用 4×4 矩阵存储四个旋转状态。基础墙踢系统处理贴墙旋转时的位移修正。

数据结构10×20 二维网格数组存储已落方块。活动方块为 4×4 旋转矩阵，通过坐标偏移映射到网格。
碰撞检测将方块的 4×4 矩阵投影到网格对应位置，检查边界溢出和已占用格。旋转时先尝试原角度，失败则依次尝试墙踢偏置。
消行算法逐行扫描满行→splice 删除→unshift 空行补充顶部。分数 = 行数² × 100，速度随等级线性递增。

一个都不能死

双通道渲染 + 渐进加速

同时控制左右两个火柴人跳过障碍，任何一个碰到障碍都会失败。考验左右手协调和节奏感。

渲染架构单 Canvas (1366×621) 分左右两个逻辑区域，独立绘制两个火柴人的动画帧和各自障碍物。
障碍生成随机间隔 + 渐进加速曲线，右侧障碍比左侧稍延迟以区分节奏。碰撞判定：火柴人碰撞框与障碍物矩形重叠即失败。
事件处理点击/触摸屏幕左半区→左侧火柴人跳跃，右半区→右侧跳跃。用 clientX 相对 Canvas 左边界判断。

扫雷

BFS 展开 + 概率推理

经典的 NP 完全推理游戏。根据数字推断地雷位置，标记所有地雷即可获胜。

数据结构二维数组存储三种信息：是否地雷、邻雷计数、是否已翻开。Fisher-Yates 洗牌算法随机布雷。
BFS 展开点击到空格（邻雷数=0）时，递归/队列展开所有相邻空格（Flood Fill），直到遇到数字边界。O(n) 复杂度。
左键+右键同时按下左右键（chord）：当标记数与数字相等时自动翻开剩余邻格，减少重复操作。

推箱子

网格编码 + 历史栈

经典的 PSPACE-完全益智游戏。只能推不能拉，一步错可能全局卡死。问题本质是状态空间搜索。

地图编码数字编码：0=空地 1=墙 2=目标点 3=箱子 4=玩家 5=箱子在目标上。100 关预置地图库 (mapdata100.js)，每关支持任意尺寸。
移动逻辑方向键驱动：检查目标格→空地则移动，箱子则再检查箱子前方→空地则推。两步联动原子操作。
撤销系统历史栈记录每步的玩家旧位置、箱子旧位置（若有），支持无限步回退。重放逆操作即可。

吃豆人

Tile 地图 + 幽灵状态机

永远经典的街机迷宫追逐游戏。地图为二维 Tile 数组，幽灵 AI 行为由有限状态机驱动。

地图表示960×640 Canvas，二维 tile 数组编码迷宫结构。每个 tile 标记为墙/豆子/大豆子/空地，吃豆人和幽灵基于 tile 坐标做离散移动。
幽灵 AI三态 FSM：追逐（追踪吃豆人位置）→ 散开（各回角落）→ 逃跑（吃到大豆子后反向逃离）。状态切换由计时器触发。
碰撞检测基于 tile 坐标的离散碰撞：吃豆人与豆子同 tile→加分；与幽灵同 tile→死亡/反杀。比像素级碰撞更稳定。

坦克大战

分层 Canvas + 对象池 + AABB

FC 红白机经典重现。双人对战或合作，消灭敌方坦克保卫基地。支持键盘双人操作。

分层渲染5 层 Canvas 叠加：墙壁层（静态地图）→ 坦克层 → 草地层（半透明覆盖）→ 特效层（爆炸动画）→ UI 层。分层避免重绘开销。
对象池模式子弹对象预分配 + 复用，避免频繁 new/GC。发射时从池中取出，命中/出界后归还。坦克同理管理生命周期。
碰撞系统AABB 矩形检测：坦克-墙壁、坦克-坦克、子弹-墙壁、子弹-坦克四类碰撞。空间分块优化减少检测对数。
操作玩家1：WASD + Space；玩家2：方向键 + Enter。N/P 切换关卡，Enter 开始。

切积木

Box2D 物理 + 鼠标切割

用鼠标划线切割积木，让顶部积木落到平台上而不坠落。物理引擎驱动真实重力与碰撞响应。

物理引擎Box2D (box2dweb) 驱动刚体模拟：重力加速度、碰撞响应、摩擦系数。积木切割后自动拆分为两个独立刚体。
切割算法鼠标轨迹与多边形求交→确定切割线→计算分割后的两个凸多边形顶点→创建新的 b2Body。非凸多边形需先三角剖分。
通关判定顶部积木在平台上保持静止 3 秒 → 过关。通过检测刚体线速度 < 阈值 + 位置在平台范围内判定。

最强眼力

HSL 色彩空间 + 指数衰减

在众多色块中找出颜色不同的那一个，考验色觉敏感度。色差随关卡指数衰减，越往后越难分辨。

色彩模型HSL 空间描述颜色：在固定 Hue/Saturation 下微调 Lightness 或 Hue 产生差异色块。人眼对不同色相的感知非线性，需经验调整步长。
难度曲线初始色差 Δ=30（易分辨），每关乘以衰减因子 0.92。第 30 关 Δ≈2.5，接近人眼色差辨别阈值（JND ~2）。
随机放置Fisher-Yates 洗牌确定不同色块的网格位置。网格从 2×2 逐步扩展到 6×6，增大搜索面积。

Kociemba 两阶段算法

双击魔方触发合法打乱，手动还原或点算法复原。复原时左侧会实时高亮当前执行的转面步骤。

Phase 1将魔方归约到 <U,D,L2,R2,F2,B2> 子群（角块方向全正确、棱块中层归位），最多 12 步。IDA* 搜索 + 剪枝表加速。
Phase 2在子群内搜索最优解（仅允许 180° 中层转动），两阶段合计通常 18–22 步，均 ≤ God's Number 20。
God's Number任意魔方状态最多 20 步可解（HTM 度量），由 Google 捐赠 35 CPU-年的计算机穷举证明于 2010 年。
